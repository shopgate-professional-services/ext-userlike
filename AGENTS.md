## Project Overview

Shopgate Connect PWA extension (`@shopgate-project/userlike`) that adds the Userlike live chat
to the app. It supports two integration methods, selected via the `integrationType` config key:

- **Widget key** – `@userlike/messenger` + `widgetKey` (introduced in 1.3.0, default).
- **JavaScript SDK file** – injects the script from `sdkUrl` and drives the global
  `window.userlike` API (the method used up to 1.2.1).

Frontend only — there is no backend (`extension/`) part.

## Tech Stack

- JavaScript (ES modules), no TypeScript, no React components.
- Shopgate PWA / Engage – platform modules are imported via `@shopgate/engage/*` only. The used
  exports (`makeGetRoutePattern`, `UIEvents`, `SHEET_EVENTS`) require PWA 6.8.0 or newer.
- `@userlike/messenger` (only runtime dependency), `glamor` for global CSS, `reselect`.
- npm; ESLint 8 with `@shopgate/eslint-config` 7.31 line.
- No tests, no CI configuration in the repo.

## Common Commands

Run inside `frontend/`:

- Install: `npm install`
- Lint: `npm run lint`

## Repository Structure

- `extension-config.json` registers a single `subscribers` component →
  `frontend/subscriptions.js`, and declares all config keys (all `destination: "frontend"`).
- `frontend/subscriptions.js` is the entry point:
  - `resolveIntegrationType()` picks the adapter: explicit `widgetKey` / `sdkUrl` wins; `auto`
    (or unset) uses `sdkUrl` only if `sdkUrl` is set and `widgetKey` is not.
  - Injects the shared global CSS (glamor) and wires PWA streams (consent, user data, logout,
    route changes) to the adapter.
- `frontend/integrations/messengerWidget.js` and `frontend/integrations/sdkScript.js` are the
  two adapters. Both receive `getAreStatisticsCookiesAccepted` and return the same interface:
  `{ init, hideWidget, showWidget, setUser, logout }`.
- `frontend/selectors.js` – `getUserData` (`{ name, email }` or `null`) and `getIsTablet`.

## Local Development Notes

- `frontend/config.json` is generated by the Shopgate tooling from the `extension-config.json`
  defaults / admin values. It is gitignored — never commit it.
- Import it as a default import with the `.json` extension (`import config from './config.json'`)
  and destructure; no named imports from JSON.
- Without the generated file, lint reports a `missing-extension-config` warning on the
  `config.json` imports. Start the frontend once with the extension attached to create it; don't
  change code or the ESLint config to hide the warning.

## Testing Notes

- There are no automated tests. Verify behavior manually in a PWA sandbox with both integration

## Project-Specific Pitfalls

- Initialization waits for cookie consent: `comfortCookiesAccepted$` /
  `getAreStatisticsCookiesAccepted` are loaded via `require()` inside `try/catch`, with a
  fallback to `appDidStart$` for older PWA versions. Keep that fallback.
- The SDK adapter relies on the global `window.userlikeReady` callback and distinguishes the
  classic "live chat" widget from the "UM" widget (`typeof window.userlike.getData`). The UM
  widget is hidden via the CSS variable `--userlike-um-display`.
- User data consent is checked inside each adapter's `setUser`, which is also used on
  mount/ready. Never pass user data to Userlike outside of `setUser`.
- In the messenger adapter, `hideWidget` / `showWidget` / `setUser` / `logout` are no-ops until
  `api.mount()` has emitted a messenger instance. The mount observable can emit again; sheet
  listeners are therefore registered only once.
- `pagesWithoutWidget` is matched exactly against route patterns; the route subscription is only
  registered when the list is non-empty.
- Global CSS uses `!important` and the PWA CSS variables `--tabbar-height`, `--footer-height`
  and `--safe-area-inset-*`; changes affect both integration methods.

## Editing Guidelines for AI Agents

- Keep `version` in `extension-config.json` and `frontend/package.json` in sync; keep `name` in
  `frontend/package.json` identical to the extension `id` (no `ext-` prefix).
- New config keys go into `extension-config.json` and the README.
- `CHANGELOG.md` follows Keep a Changelog (`## [x.y.z] YYYY-MM-DD`) and lists released versions
  only — no beta/alpha entries.
- Integration-specific logic belongs in the matching adapter under `frontend/integrations/`;
  shared wiring and CSS stay in `frontend/subscriptions.js`.
